# Review of audit-fixes — 2026-11-19

I found 17 problems that need action. The most serious are four new or partly fixed issues in the daemon, the systemd units and the symlink handling. Nothing was edited or committed.

**Checks run:** `cargo test --workspace --no-fail-fast` passes in every crate. The only failures are the 9 Unix-socket tests in `vec-daemon/server.rs`, which the sandbox blocks. Clippy printed no warnings or errors. Most audit items do hold, and I re-checked them in the code:
- **Store:** atomic `replace_file`; the `[`/`*`/`?` and `/a` vs `/abc` path filters (range scan); NaN skipping; `is_gone`; vector length checks.
- **Indexer:** chunker coverage; `chunk_size = 0`; relative `db_path`; `diff` sharing the walker.
- **Core:** `load_embedder` returning `Result`; the private LAN address removed (no private IP left anywhere; only `127.0.0.1` in tests); config validation; a capped final-component `O_NOFOLLOW` read.

## Findings, most severe first

1. **One local user can stall the system daemon for everyone** (medium-high, high confidence). `crates/vec-daemon/src/server.rs:308-397`. `io_timeout_ms` applies to each `read()` call, not to a whole request. A client sending one byte every 9 s holds its slot forever, and 16 such clients fill `max_connections` on a 0666 socket. Other clients then wait in the backlog and time out. `Searcher::embed` (`crates/vec-query/src/lib.rs:180-186`) returns that error instead of embedding in-process, so every user's `vec` search fails. Fix: a deadline per request (time left recomputed before each read), and fall back in-process when the daemon is busy or times out. This is the server side only, separate from the client timeout work.

2. **Requests can blow up into huge replies** (medium, high). In `server.rs:359-397`, `max_request_bytes` limits only the input. A 1 MiB request can hold 262,143 empty texts, which means 262k inferences and a reply of about 805 MB (768 floats × 4 bytes each), built whole by `encode_vectors_reply` (`protocol.rs:83`). With 16 connections that is an out-of-memory risk. Fix: a new `[daemon] max_texts_per_request` key, or reject when count × dim × 4 is above a configured limit.

3. **`PrivateTmp=yes` in the system watch and updatedb units** (medium, high). `contrib/vec-watch.service` and `contrib/vec-updatedb.service`. These services now see an empty private `/tmp` and `/var/tmp`, and `defaults.toml` does not exclude `tmp`. `updatedb` and `gc` prune every existing record there (`is_gone` sees NotFound), and new files there are never indexed. This is a silent behaviour change. Fix: drop `PrivateTmp`, or exclude `tmp` explicitly and document it.

4. **The symlink race is fixed only for the last path component** (medium, high). `crates/vec-index/src/lib.rs:881-925`. A user can swap one of their own directories for a symlink (for example to `/root`) between the walk and the `open`. The indexer, running as root, then reads and embeds a root-only file and stores it under the user's path. The user swaps the link back, passes `can_read`, and can probe that file through search or `similar`. Fix: compare `(st_dev, st_ino)` from `fstat` on the open file with the walker's `lstat`, or use `openat2(RESOLVE_NO_SYMLINKS)`.

5. **`--full` wipes the index on any `ensure_model` error** (medium, high). `vec-index/src/lib.rs:518-528`. Any `Err`, including SQLITE_BUSY after `busy_timeout_ms` or an I/O error, is treated as a model mismatch. `reset_to` is set and the whole index is emptied at the first write. Files whose read then fails, which are normally kept, are lost. Fix: have vec-store return a typed `ModelMismatch` error and reset only on that.

6. **One file that always fails to embed blocks indexing for good** (medium, medium). `lib.rs:684-724`. If such a file is alone in a flush, `any_embedded` stays false and the run is reported as "backend down". That happens when it is the first pending file and has at least `batch_size` chunks, or in the last flush. `updatedb` then fails on every run with nothing pruned, and `vec watch` retries forever. Fix: before blaming the backend, embed one probe text; only if the probe also fails, stop the run.

7. **Any problem with the daemon makes searches fail outright** (medium, high). `vec-query/src/lib.rs:180-186`. This covers a model mismatch, a protocol error and a timeout, and it contradicts the module doc ("the daemon when it serves that model, else in-process"). After a package upgrade, an old v1 daemon that is still running answers the new handshake with "request too large", so every query fails until it is restarted. Fix: warn and fall back in-process.

8. **A concurrent `--full` reset can let old-model vectors in** (low-medium, medium). `vec-store/src/lib.rs` `replace_file` checks only the dimension. A watcher that passed `ensure_model` before another process's `reset_model` can still write old-model vectors of the same dimension. Fix: pass `&ModelIdentity` to `replace_file` and compare inside its transaction.

9. **Every in-process query now hashes the whole model file** (low-medium, high). `vec-query/src/lib.rs:188-191` calls `identity_with_sha` once per process. Hashing the local 340 MB int8 model took 0.64 s with a warm cache, added to each `vec` call. The daemon's startup hash also delays its first, socket-activated reply. Fix: cache the hash keyed by path, size, mtime and inode, or let readers check name, dimension and file size only.

10. **`vec status`, `vec doctor` and MCP `index_status` start the daemon** (low-medium, high). `vec-query/src/status.rs:158` does a handshake. With socket activation, that alone starts the daemon, loads the model and hashes it. Fix: skip the probe when nothing is listening, or put it behind a flag.

11. **Schema migration under contention** (low-medium, medium). `vec-store/src/lib.rs:813-860`. The migration rewrites every vector in one IMMEDIATE transaction. A second process opening the database waits 5 s and then errors out. `vec-watch.service` (5 restarts in 60 s, `RestartSec=5s`) can hit its start limit and stay down if migrating a large index takes more than about 25 s. Queries fail until the migration commits. Fix: retry the migration lock with backoff, or document running `vec updatedb` once after the upgrade.

12. **`similar` and `explain` do not check that the user can read the source file** (low, high). `vec-query/src/lib.rs:267` and `:297`. They use the stored vector, or show the hash and byte ranges, of a file the caller cannot read. That is inconsistent with the per-user access model, though low impact because the database is world-readable anyway. Fix: require `can_read(path)`.

13. **The upgrade breaks some existing configs** (low, high). In `config.rs:46`, `[embed] daemon_socket` is now a hard error, and so are relative paths and out-of-range values. After an upgrade, every command fails, including the services. Fix: for one release, warn and map the old key to `[daemon] socket`.

14. **Hardcoded values left under your config rule** (low):
   - `ERROR_BODY_PREVIEW_CHARS = 200` (`vec-embed/src/lib.rs:673`) is a limit and belongs in config.
   - `OUTPUTS` and `PAD_TOKENS` (`:323-330`) are model-specific names; these are arguably model-format knowledge rather than tunables.
   - `/run/vec/embed.sock` is repeated in the `.socket` unit, which is unavoidable and documented.
   - Everything else is in `defaults.toml` or `locations.toml`.

15. **Dead or redundant code:**
   - `Store::get_missing_file_paths`, `delete_all_files` and `delete_missing_files_under` are used only by tests.
   - `Embedder::is_stub` is unused outside its test.
   - The `TAKEN` guard in `activation.rs` protects a function called once per process.
   - `resolve_path_filter` (`vec-index:403`) re-implements `util::absolute_lexical`.

16. **Help text is wrong** (low). `crates/vec-cli/src/main.rs:89` says "the old entries stay searchable until replaced". When the model changes, the index is emptied at the first write.

17. **`snippet_lines` is used as a radius** (low). It is documented as "lines … shown" but 2n+1 lines are shown. Rename it or fix the doc.
